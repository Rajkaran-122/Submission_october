Improvements verified by this harness:

- **Numeric (natural) case-id sort** — canonical order is `case_33 < case_99 <
  case_100 < case_550`; the full-dataset `output.csv` content now validates
  contract-clean and the validator treats plain lexicographic order as a
  warning only (not an error).
- **Citation fallback** — when the freshest observation is a post-`audit_at`
  export, citable evidence is used instead; the independent citation-window case
  and the sample evidence accuracy (1.0000) verify it.
- **No-finding filter for anonymous rows** — eliminated the earlier
  over-reported anonymized-analytics verification steps (`case_09`, `case_24`,
  `case_25`, `case_26` in the earlier run).
- **Legal-register decoy exclusion** — legal-hold samples no longer attract
  unrelated retained records.
- Status decisions are 100% on both the development regression set and the 13
  independent cases; mutation/transform tests prove claim- and order-independence.

## (g) Known limits / unverified items

- No hidden canonical answers are available; the 32 public samples are a
  development regression set. Nothing here claims hidden-set or generalisation
  accuracy.
- Resource-id ambiguity can still cost step points: anonymous-analytics row
  attribution ties, simultaneous-case account baselines, and the
  support-message-vs-attachment category for `evidence_61` are measured as
  step-level misses above, not papered over.
- The harness runs the pipeline with `--skip-images` for determinism/portability;
  the final submission run may additionally use PNG OCR (macOS Vision), so
  image-only evidence cases can differ between the two runs.
- The 13 independent cases are small (one request per dataset) by construction;
  they exercise the rules directly and are independent of, not a substitute for,
  the official grader.
- `evaluation/reports/*.json` are the machine-readable sources for every number in
  this file; refresh them (`samples`, `cases`) after any pipeline change before
  packaging `code.zip`.
