# Evaluation harness (`evaluation/`)

Independent evaluation for the "Ghost Data Still Exists" submission. The harness
never imports `ghost_audit.planner`/`ghost_audit.scenario`; expected answers are
either the published 32-case `sample_output.csv` or hand-written
`evaluation/cases/*/expected.csv` files. The pipeline CLI under test is:

```bash
python -m ghost_audit run --dataset DIR --requests CSV --output CSV [--skip-images]
```

## What it does

| Function | Purpose |
|---|---|
| `validate_output(output_csv, requests_csv=None, dataset_dir=None)` | Strict contract validator: exact header, one sorted row per request, 7-field steps, allowed phase/operation/state triples, consecutive `step_no`, phase and within-phase ordering, per-status rules (NOT_APPLICABLE `[]`, COMPLETE verification-only with evidence, INCOMPLETE findings + empty remediation/future evidence), and evidence citations that really exist and are `<= audit_at`. |
| `evaluate_predictions(pred_csv, gold_csv, requests_csv=None, dataset_dir=None)` | Case-level status accuracy, multiset step precision/recall/F1, exact sequence accuracy, ordered-treatment accuracy, field-level accuracy, evidence accuracy, contract issues and per-case diagnostics. |
| `sample_regression(...)` | Official 32-case public sample regression (gold = `sample_output.csv`); runs the pipeline on `sample_deletion_requests.csv` when no predictions are supplied. |
| `run_cases(...)` | Runs/loads predictions for every independent case and scores them against the hand-written `expected.csv`. |
| `Report.summary()` / `write_json()` / `write_markdown()` | Human-readable failure report, machine-readable JSON, Markdown report section. |

### Metric definitions

- **status accuracy** - fraction of cases whose `deletion_status` equals gold.
- **step precision / recall / F1** - multiset match of the 5-field treatment key
  `(phase, operation, state, system_id, resource_id)`; evidence and step number
  are scored separately.
- **sequence accuracy** - fraction of cases whose complete ordered
  `steps_json` (including `step_no` and `evidence_id`) equals gold exactly.
- **ordered treatment accuracy** - same ordered treatment sequence, ignoring
  evidence/step numbers (separates ordering errors from evidence errors).
- **field-level accuracy** - per-field / overall agreement across index-aligned
  steps (denominator = max(gold_steps, pred_steps) per case).
- **evidence accuracy** - among positions whose treatment matches, the fraction
  whose `evidence_id` matches gold.
- **contract errors/warnings** - output from `validate_output` (when a dataset
  directory is supplied, invalid/out-of-window citations are errors).

The 32-case sample set is a **development regression set**, not a hidden-set
accuracy claim; reports are labelled accordingly.

## Usage

```bash
# 1. Contract validation of any output.csv
uv run python evaluation/evaluate.py validate \
  --output output.csv \
  --requests docs/refs/hackerrank-orchestrate-october26-main/dataset/deletion_requests.csv \
  --dataset  docs/refs/hackerrank-orchestrate-october26-main/dataset

# 2. Official 32-case sample regression (runs the pipeline itself)
uv run python evaluation/evaluate.py samples --json evaluation/sample_report.json

# 3. Score an arbitrary prediction file against a gold file
uv run python evaluation/evaluate.py regress \
  --pred output.csv --gold path/to/gold.csv \
  --requests path/to/requests.csv --dataset path/to/dataset \
  --markdown evaluation/evaluation_report.md

# 4. Team-authored independent cases (12 mini-datasets, hand-written answers)
uv run python evaluation/evaluate.py cases --run-pipeline

# 5. Pipeline-free fixture self-check
uv run python evaluation/evaluate.py cases --predictions-dir <dir-with-case-csvs>
```

Exit codes: `0` clean, `1` contract errors or metric regressions, `2` missing
pipeline / invocation error. Machine-readable reports use `--json`; the
Markdown section written with `--markdown` is meant to be folded into the
submission's `evaluation/evaluation_report.md` (the narrative parts are filled by
the team; no numbers are fabricated).

## Files

- `evaluate.py` - the harness (stdlib only; importable and runnable).
- `cases/` - 12 independently authored mini-datasets with hand-written
  `expected.csv` and rule-traceable `README.md` rationale
  (see `cases/README.md` for coverage).
- `failure_report.md` - skeleton for the Lead to fill with real run results.
- `evaluation_report.md` - submission evaluation report (draft generated by the
  harness from real runs; the Lead re-runs and refreshes it before packaging).
- `reports/` - machine-generated JSON/Markdown sections for the latest
  `samples` / `cases` runs (no numbers are hand-typed).

## Tests

```bash
UV_CACHE_DIR="$PWD/.uv-cache" uv run pytest -q tests/test_eval_*.py
```

- `test_eval_contract.py` - validator positive/negative fixtures, evidence
  window, official sample self-check.
- `test_eval_metrics.py` - metric math on static gold/mutation fixtures + CLI
  exit codes.
- `test_eval_cases.py` - fixture integrity + end-to-end pipeline vs hand-written
  answers (skips until the `python -m ghost_audit` CLI exists).
- `test_eval_transforms.py` - request-row shuffle / reported_status change /
  decoy records must not change predictions (pipeline tests skip until CLI).
- `test_eval_mutations.py` - the evaluator must catch trusting
  `reported_status`, ignoring historical email, dropping remediation and wrong
  step order.

The end-to-end/transform tests **skip** only when the pipeline CLI is absent.
CI gating thresholds (also documented in `evaluation/evaluation_report.md`):

| Run | Gate |
| --- | --- |
| official 32 samples (development regression set) | status accuracy == 1.0; step F1 >= 0.90; exact sequence accuracy >= 0.65; contract errors == 0 |
| 13 hand-authored independent cases | status accuracy == 1.0; step F1 == 1.0; exact sequence accuracy == 1.0; contract errors == 0 |
| transform checks (shuffle / `reported_status` / decoys) | per-case predictions identical to baseline |
| mutation checks | 5/5 injected classic bugs reported as failures |

Run commands:

```bash
UV_CACHE_DIR="$PWD/.uv-cache" uv run pytest -q tests/test_eval_cases.py tests/test_eval_transforms.py
uv run python evaluation/evaluate.py samples
uv run python evaluation/evaluate.py cases --run-pipeline
```
