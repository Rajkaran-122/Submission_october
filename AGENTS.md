# AGENTS.md — Ghost Data Still Exists (local working rules)

This file defines the local working rules for the HackerRank Orchestrate "Ghost Data Still Exists" project.
If in conflict with user instructions, user instructions take precedence.

## 0. Project Scope

- Target repository: https://github.com/Rajkaran-122/Submission_october.git
- Challenge: https://www.hackerrank.com/contests/hackerrank-orchestrate-october26/challenges/ghost-data-still-exists
- Read-only reference directory: `docs/refs/hackerrank-orchestrate-october26-main/` (**do not modify, do not commit**).
  Contains `AGENTS.md`, `README.md`, `problem_statement.md`, and `dataset/` as the problem description and official sample sources.
- Deliverables directory: `submission/` (`output.csv`, `code.zip`, `log.txt`, `INTERVIEW_GUIDE.md`).
- Session log: The root `log.txt` is an append-only agent session record; `submission/log.txt` is generated by `scripts/build_transcript.py` as root `log.txt` (PART I, verbatim prefix) + session appendices (PART II). The latter is uploaded to HackerRank.
- Raw session exports: `.conversations/` (raw session exports, if present). Treated as machine-specific inputs, **gitignored, not included in code.zip**; only sanitized `submission/log.txt` is submitted.

## 1. Environment

- Python version: pinned in `.python-version` (3.13), dependencies managed via **uv** in `.venv`.
- Sandbox caching: if the global cache is restricted, specify a local cache directory:

  ```bash
  export UV_CACHE_DIR="$PWD/.uv-cache"
  uv sync
  uv run pytest
  ```

- Run full pipeline (requires official dataset in the reference directory):

  ```bash
  uv run python -m ghost_audit run \
    --dataset docs/refs/hackerrank-orchestrate-october26-main/dataset \
    --output output.csv
  ```

- Screenshot evidence (PNG) OCR: uses `scripts/ocr_images.swift` (macOS Vision). OCR cache is stored in `work/ocr/` and excluded from deliverables.

## 2. Key Constraints (from Challenge Statement)

- Only use participant-facing files in `dataset/`; do not use any organizer-only ground truth.
- Do not modify official sample answers or input data to make tests pass.
- Only evidence captured at or before `audit_at` (`captured_at <= audit_at`) may determine case status; evidence after `audit_at` may only serve as static identity corroboration and must be documented.
- `reported_status` and activity `reported_result` are claims only and cannot serve as proof of completion.
- Final `output.csv` must have exactly 518 data rows sorted ascending by canonical numeric `case_id`; `steps_json` is an ordered JSON array with consecutive `step_no` starting at 1.
- Deliverables must not include dataset, `.venv`, caches, nested archives, API keys, or credentials.

## 3. Git / GitHub Workflow

- Feature Branch: one issue per branch; English commit messages.
- For each branch, create a PR, self-review, ensure CI passes, then squash merge.
- GitHub operations are restricted to the target repository issues, PRs, branches, Project tracker, and repository contents.

## 4. Acceptance Criteria

1. `uv run pytest` all pass (dataset-dependent tests skip when dataset is absent).
2. `output.csv` passes contract validation and official sample regression (sample metrics recorded in `evaluation/evaluation_report.md`).
3. `code.zip` reproduces cleanly when extracted into a fresh directory according to README.
4. Root `log.txt` adheres to format rules (`tool=` and `model=` lines); `submission/log.txt` retains root log as a verbatim prefix and contains generated PART II appendices (`python3 scripts/build_transcript.py --check` must PASS).
5. `submission/` contains exactly the four deliverables; interview guide is complete and contains no placeholders.
6. All open questions and unresolved items are documented in `docs/planning/`.
